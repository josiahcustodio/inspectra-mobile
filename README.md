# Clowtec Inspector App (Inspectra)

A high-performance, offline-first Flutter mobile application tailored for City Health Office inspectors to streamline their field operations, inspections, and data collection.

---

## 🚀 Getting Started

1. **Clone the repository.**
2. **Setup your environment variables:**
   Copy the contents of `.env.example` into a new `.env` file at the root of the project and populate it with your actual Firebase credentials.
3. **Get packages:**
   ```bash
   flutter pub get
   ```
4. **Run the app:**
   ```bash
   flutter run
   ```

> If there are errors, especially about undefined directories or functions, run:
> ```
> flutter clean
> flutter pub get
> ```
> Then press `Ctrl+Shift+P` and choose **Dart: Restart Dart Analyzer**, then run `flutter run`.

## 📱 Features & Capabilities

- **Offline-First Architecture**
  - Uses `Hive` for robust local data storage, allowing inspectors to work in areas with poor or no internet connectivity.
  - Synchronizes inspection templates, establishment data, and pending submissions (offline queue) automatically or manually with `Firebase/Firestore` when internet is available.

- **Establishment Browsing (read-only)**
  - Search and view the cached database of registered establishments, offline.
  - Each record shows **business name, owner name and address only**. Barangay, personnel counts, health-certificate counts, permit/control numbers and the category badge are stored on the record but deliberately not shown on mobile.
  - Tapping a record **starts its inspection**; there is no create, edit or delete. The web admin dashboard is the sole owner of establishment data, so the two clients can never blank each other's fields.

- **Smart Inspection Forms**
  - Dynamic rendering of checklists based on the specific category of the establishment (e.g., Public Places, Food, Supermarket).
  - Categorized checklist sections and easy pass/fail judgments.
  - Real-time scoring and calculation engine that outputs immediate ratings (e.g., "Excellent").

- **Robust Evidence Collection**
  - Take Photo Evidence natively inside the application via `image_picker`.
  - Inspector and Owner digital signature capture for instant verification using `signature`.
  - Securely uploads files to cloud storage upon synchronization.

- **QR Code Scanning Integration**
  - Fast establishment lookup through the built-in QR Code scanner leveraging `mobile_scanner`.

- **Modern & Professional UI/UX**
  - A Sage Green inspired professional design system.
  - Bento-layout dashboard providing quick glances at pending inspections, synced items, and recent activity.
  - Easy-to-use search and primary action placement.

#### `lib/data/models/`

| File | Purpose |
|---|---|

| `inspection_log.dart` | Plain Dart model (not Hive) for a completed inspection record. #### `lib/data/services/`

| File | Purpose |
|---|---|
| `auth_service.dart` | Static service wrapping Firebase Auth. Methods: `signInWithGoogle()` (popup for Web, native for mobile), `signInWithEmailPassword()`, `signUpWithEmailPassword()` (also sets display name), `sendPasswordResetEmail()`, `signOut()`. Exposes `currentUser` and `authStateChanges` stream. |
| `offline_service.dart` | Manages all local Hive storage and the **download** half of sync. Registers Hive adapters for `Establishment` and `ChecklistTemplate`. `syncData()` fetches categories, establishments and checklist templates from Firestore into local Hive boxes — parsing each snapshot *completely* before replacing its box, so a single type-drifted document can no longer leave the device with an empty cache. Its establishment pass carries `[REF: ESTABLISHMENT_UPGRADE_BRIDGE]`, a temporary branch that preserves an establishment an older build created offline (and never uploads it); it is removed one release from now. Read helpers: `readPref()`, `writePref()`, `getLocalEstablishments()`, `getEstablishmentById()`, `getLocalTemplatesByCategory()`. Exposes the `inspectionsQueueBox` for the offline submission queue. ##### `inspection_form_screen.dart`
**Purpose:** The active inspection execution screen. Dynamically loads `ChecklistTemplate` items by establishment category and renders them as `ChecklistItemCard` widgets grouped by sub-category. The body is a `Column` of **two pinned blocks over one scrolling list**: an `EstablishmentBanner` identity strip (business name / owner / address), then the sticky real-time score header, then an `Expanded` `SingleChildScrollView` holding the checklist, a Remarks/Notes `TextFormField` and a Photo Evidence tap-to-capture section. | Category | Details |
|---|---|

| **Gesture Detectors** | `GestureDetector` on the Photo Evidence container → calls `_pickImage()` which opens the device camera via `image_picker`. |

| **Snackbars** | Checklist incomplete: "Please answer all checklist items before submitting." Submit online success: "Submitted Successfully!". Saved offline: "Saved offline. Will sync later." |

> **Two things in `build()` that look like mistakes and are not.**
>
> 1. **The business name is rendered twice** — once in the app bar, once in the banner. The banner is removed outright while a keyboard is open (`[REF: BANNER_KEYBOARD_YIELD]`), because the two pinned children are inflexible and once they exceed the body height the `Expanded` is clamped to zero and the checklist is clipped silently in release (reachable at 320x568, text scale 2.0, keyboard up). That window is not rare or late: marking an item FAIL reveals a required deficiency-notes field *inline, mid-checklist*, so the keyboard opens while the inspector is scoring. The app bar copy sits outside the body `Column`, costs no vertical space and never yields, so it — not the banner — is what guarantees the name stays on screen. **Do not de-duplicate them.**
> 2. **`MediaQuery.viewInsetsOf(context).bottom` is read above the `Scaffold`, not inside the body.** `Scaffold` strips the bottom inset from its own body (`removeViewInsets(removeBottom: true)` while `resizeToAvoidBottomInset` is on), so the identical call from a `Builder`, a `LayoutBuilder` or the banner itself reads a constant zero — no warning, no exception, the guard just never fires.
>
> The body is deliberately **not** a `CustomScrollView` with `SliverPersistentHeader`s: every delegate must declare `minExtent`/`maxExtent` in logical pixels, and neither pinned block has a knowable height (both scale with `MediaQuery.textScaler`; the banner also depends on whether its address wraps).

## 🔐 Security Context & Best Practices

- Requires `google-services.json` (Android) or `GoogleService-Info.plist` (iOS) from the Firebase Console for Auth and Firestore access.
- Offline data stored in Hive is unencrypted. Ensure physical device security protocols are observed during field use.
- Firestore Security Rules govern data access and insertion on the backend. Note what they do **not** do: the `establishments` write rule is intentionally `isAuthorized()`, not `isAdmin()`, because the web admin dashboard lets officer-role users create and edit establishments and narrowing it would lock them out. That the mobile app never writes establishments is enforced by there being no write call in `sync_service.dart`, not by a rule. The reasoning is recorded as a comment on the `establishments` match block in `firestore.rules`.
- Offline data in Hive is keyed by field *number*. Never remove or renumber a `@HiveField` on a model that has already shipped — it corrupts the stored box on upgrade. Fields that stop being used are left declared.
- `.env` file (if used for any remaining config) must never be committed to version control — it is listed in `.gitignore`.
