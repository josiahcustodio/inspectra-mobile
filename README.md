# Clowtec Inspector App (Inspectra)

A high-performance, offline-first Flutter mobile application tailored for City Health Office inspectors to streamline their field operations, inspections, and data collection.

---

## 🚀 Getting Started

1. **Clone the repository.**
2. **Setup your environment variables:**
   Copy the contents of `.env.example` into a new `.env` file at the root of the project and populate it with your actual Firebase credentials.
3. **Get packages:**
   ```bash
   flutter pub get
   ```
4. **Run the app:**
   ```bash
   flutter run
   ```

> If there are errors, especially about undefined directories or functions, run:
> ```
> flutter clean
> flutter pub get
> ```
> Then press `Ctrl+Shift+P` and choose **Dart: Restart Dart Analyzer**, then run `flutter run`.

## 📱 Features & Capabilities

- **Offline-First Architecture**
  - Uses `Hive` for robust local data storage, allowing inspectors to work in areas with poor or no internet connectivity.
  - Synchronizes inspection templates, establishment data, and pending submissions (offline queue) automatically or manually with `Firebase/Firestore` when internet is available.

- **Establishment Management**
  - Search and view a database of registered establishments.
  - Add new establishments dynamically, with automatically updated "Type of Establishment" categories fetched from the Firebase backend.
  - Track basic setup data, employee count, health certificates, and sanitary permit control numbers.

- **Smart Inspection Forms**
  - Dynamic rendering of checklists based on the specific category of the establishment (e.g., Public Places, Food, Supermarket).
  - Categorized checklist sections and easy pass/fail judgments.
  - Real-time scoring and calculation engine that outputs immediate ratings (e.g., "Excellent").

- **Robust Evidence Collection**
  - Take Photo Evidence natively inside the application via `image_picker`.
  - Inspector and Owner digital signature capture for instant verification using `signature`.
  - Securely uploads files to cloud storage upon synchronization.

- **QR Code Scanning Integration**
  - Fast establishment lookup through the built-in QR Code scanner leveraging `mobile_scanner`.

- **Modern & Professional UI/UX**
  - A Sage Green inspired professional design system.
  - Bento-layout dashboard providing quick glances at pending inspections, synced items, and recent activity.
  - Easy-to-use search and primary action placement.

## 📁 Detailed Project Structure & File Descriptions

### Root: `lib/`

| File | Purpose |

### `lib/data/`
All data layer logic: models, local storage, and remote API services.

#### `lib/data/models/`

| File | Purpose |
|---|---|
| `establishment.dart` | Hive-persisted data model (`@HiveType(typeId: 0)`) for a registered establishment. Fields: `id`, `name`, `category`, `address`, `ownerName`, `personnelCount`, `personnelWithHc`, `sanitaryPermitNo`, `controlNo`. Includes `fromJson()` (Firestore → model) and `toJson()` (model → Firestore map). |
| `establishment.g.dart` | Auto-generated Hive TypeAdapter for `Establishment`. Enables Hive box serialization. **Do not edit manually.** |
| `checklist_template.dart` | Hive-persisted data model (`@HiveType(typeId: 1)`) for a single inspection checklist item. Fields: `id`, `category`, `subCategory`, `item` (question text), `weight` (demerit value on fail). Includes `fromJson()` for parsing Firestore data. |
| `checklist_template.g.dart` | Auto-generated Hive TypeAdapter for `ChecklistTemplate`. **Do not edit manually.** |
| `inspection_log.dart` | Plain Dart model (not Hive) for a completed inspection record. Fields: `id` (UUID auto-generated), `establishmentId`, `inspectorName`, `totalDemerits`, `percentageRating`, `remarks`, `inspectionDate`, `photoEvidenceUrl`, `localPhotoPath`, and `offlineResults` (embedded per-item results for offline replay). Provides `toJson()` for Hive queue and `toFirestoreJson()` which strips `offlineResults` before remote upload. |

#### `lib/data/services/`

| File | Purpose |
|---|---|
| `auth_service.dart` | Static service wrapping Firebase Auth. Methods: `signInWithGoogle()` (popup for Web, native for mobile), `signInWithEmailPassword()`, `signUpWithEmailPassword()` (also sets display name), `sendPasswordResetEmail()`, `signOut()`. Exposes `currentUser` and `authStateChanges` stream. |
| `offline_service.dart` | Manages all local Hive storage. Registers Hive adapters for `Establishment` and `ChecklistTemplate`. `syncData()` fetches categories, establishments, and checklist templates from Firestore and stores them in local Hive boxes. Also provides helpers: `getLocalEstablishments()`, `getEstablishmentById()`, `getLocalTemplatesByCategory()`, `updateLocalEstablishment()`, `deleteLocalEstablishment()`. Exposes the `inspectionsQueueBox` for the offline submission queue. |
| `sync_service.dart` | Handles all Firestore and Firebase Storage remote operations. Key methods: `uploadImage()` / `uploadBytes()` (Firebase Storage), `submitInspectionLog()`, `submitInspectionResults()` (per-item results as Firestore sub-collection), `syncPendingInspections()` (flushes offline queue), `syncSingleInspection()`, `fetchInspectionHistory()`, `fetchInspectionDetails()`, `insertEstablishment()`, `updateEstablishment()`, `deleteEstablishment()`, `fetchCategories()`. |

---

### `lib/providers/`
Reactive state management using the `provider` package (`ChangeNotifier`).

| File | Purpose |
|---|---|
| `auth_provider.dart` | Wraps `AuthService` for reactive auth state. Manages `isLoading` and `errorMessage`. Methods: `signInWithGoogle()`, `signInWithEmailPassword()`, `signUpWithEmailPassword()`, `sendPasswordResetEmail()`, `signOut()`. Listens to Firebase `authStateChanges` stream and calls `notifyListeners()` on changes. |
| `rating_provider.dart` | Manages real-time inspection scoring state. Stores per-item `answers` (Pass/Fail) and `itemNotes` (deficiency text). Computes `totalDemerits`, `score` (0–100 clamped), `isCompleted` (all items answered), and `ratingLabel` (`Excellent` ≥90, `Very Satisfactory` ≥70, `Satisfactory` ≥50, `Action Required` <50). Methods: `setAnswer()`, `setNote()`, `initWeights()`, `reset()`. |
| `pending_inspections_provider.dart` | Tracks the offline `inspections_queue` Hive box. Provides `pendingCount`, `pendingItems`, `isSyncing`. Listens to Hive box changes live via `.listenable()`. Methods: `submitAll()` (bulk sync all pending via `SyncService`), `submitSingle(id)` (sync one item). |
| `inspection_history_provider.dart` | Fetches and merges inspection history from remote Firestore and the local offline queue. Provides `logs`, `establishmentNames`, `isLoading`, `error`, `isEmpty`. Deduplicates by ID and sorts by date descending. Methods: `fetchHistory()`, `refresh()`. |

## 🔐 Security Context & Best Practices

- Requires `google-services.json` (Android) or `GoogleService-Info.plist` (iOS) from the Firebase Console for Auth and Firestore access.
- Offline data stored in Hive is unencrypted. Ensure physical device security protocols are observed during field use.
- Firestore Security Rules govern data access and insertion on the backend.
- `.env` file (if used for any remaining config) must never be committed to version control — it is listed in `.gitignore`.
